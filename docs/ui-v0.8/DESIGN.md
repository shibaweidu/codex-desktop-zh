# v0.8 界面设计原型

这是下一版界面的**设计评审原型**，不是 v0.8 的正式发行版。本目录保留设计阶段的独立原型与当时的测试记录；原生实现现已位于 src/ 与 macos/，其验收见 ../NATIVE-v0.8-VERIFICATION.md，不能用原型测试替代正式程序验收。

本原型冻结于“官方源与社区源可选”的早期方案。后续产品要求已改为**客户端更新只使用 Wangnov 社区镜像、自动识别平台/架构与本机版本**；因此下面的来源选择器、架构手选及对应测试是历史设计记录，不代表当前 WPF / SwiftUI 实际行为。

## 查看

直接用浏览器打开同目录 `index.html`，无需安装依赖、启动服务或联网。CSS、图标与交互均在本地；只有点击外部来源链接才访问网站。

原型状态为示例，不扫描应用、不访问账户、不启动或关闭进程、不注入 Codex、不下载安装包。主题偏好保存在当前浏览器的 localStorage，受浏览器本地文件策略影响；设置与真实 Codex 相互独立。

## 设计方向与评审

定位是轻量的本地桌面控制台，不是下载站或后台仪表盘。沿用用户确认的深色、淡紫色方向；按本轮要求，采用接近 macOS 的磨砂材质、圆润控件与轻微立体感。不加入营销大字和冗长操作说明。首页一个主要动作，安装信息与启动偏好一起呈现；操作记录不藏在成功提示后面。

视觉记忆点放在带有接触阴影和边缘高光的图标、主按钮；主题缩略图继续直观展示配色。渐变只描述材质受光和窗口外的桌面背景，不用霓虹光晕装饰内容。排除了常见的等大统计卡片、虚构使用数据和宣传轮播。图标为本项目手绘的 SVG 线性图标，不打包官方 Logo 或社区人物图片。

### 本轮材质调整

- `styles.css` 保留基础组件和布局，`apple-materials.css` 集中定义新的视觉材质，避免改变业务交互。
- 四层深度：窗口投影 → 磨砂侧栏 → 轻微悬浮面板 → 内凹日志与输入框。不是给所有元素添加同样的厚阴影。
- 图标采用圆角方块、浅顶光和底部接触阴影；主按钮采用淡紫色微渐变，并提供轻微按压反馈。
- 赞助入口移至左侧栏下方，位于安装状态与设置之前；只保留一份链接，窄屏时也在导航左下方显示。不做顶部横幅。
- 继续保留适合 Windows 的右上角窗口操作示意，不为了苹果观感硬套红黄绿按钮。正式 macOS 版仍使用系统原生窗口控件。
- 透明效果不受支持时使用实色；系统减少透明度/动态效果偏好下减少材质模糊/位移。高对比主题使用实色表面。
- 使用 `frontend-design` 与 `ui-ux-pro-max`：没有采用数据库默认的青色仪表盘方案，而是保留用户确认的淡紫色及本地桌面软件结构。

### 信息架构

```text
系统标题栏                     原型标识      最小化 / 最大化 / 关闭
磨砂侧栏            工作台路径
  概览              页标题与简要状态
  下载 Codex        主操作区域                   辅助信息
  界面汉化          最近操作 / 进度 / 验证报告
  主题外观
  日志诊断
  赞助卡片（左侧）
  设置与关于        本地状态栏                     查看记录
```

所有页面左对齐。窄窗将辅助信息向下折叠，手机宽度改为顶部分栏导航，保留关于入口。生产版继续使用 WPF / SwiftUI，不因为 HTML 原型而迁移到 Electron / Tauri。

## 可点击流程

1. **概览**：汉化启动演示、英文启动演示；运行后再次启动弹关闭确认。取消不改变状态。确认只写入原型日志。
2. **下载**：此历史原型可切换系统、架构及官方/社区镜像；版本与格式分开显示；确认后模拟获取进度，支持取消。没有真实传输、哈希校验或安装。生产版本已改成固定社区镜像并自动检测平台、架构和本机版本。
3. **汉化**：识别安装、设置语言、页面验证、菜单检查分开呈现，后两项保持待验证，不把请求成功冒充汉化成功。
4. **外观**：六种自有纯色预设；选择只预览，应用才保存。Codex 外观只保存设计偏好，尚未连接注入；工具外观可改变原型配色及材质底色。字体大小控制预览，不改变真实 Codex。
5. **诊断**：搜索、级别筛选、复制、导出原型事件；运行检查明确记录后端未接入。
6. **关于**：当前发行版快照、设计预览版本、更新页面、反馈与仓库链接、检查更新开关示意。没有新增生产自动更新逻辑。

## 下载来源及接入决策

核实数据快照见 `download-sources.json`；只作为设计研究资料，不能直接当生产配置。

- Codex 本体：Windows 官方为 [Microsoft Store](https://apps.microsoft.com/detail/9plm9xgg6vks)，macOS 为官方 [Apple Silicon DMG](https://persistent.oaistatic.com/codex-app-prod/Codex.dmg) / [Intel DMG](https://persistent.oaistatic.com/codex-app-prod/Codex-latest-x64.dmg)。**不是本工具自己的 EXE / ZIP。**
- [codex-app-mirror](https://github.com/Wangnov/codex-app-mirror) 提供社区分发、[版本清单](https://codexapp.agentsmirror.com/latest/manifest)及校验信息。当前产品更新流程只使用该镜像；原型中的官方源选项仅为历史评审内容。
- [Codex-App-Manager](https://github.com/Wangnov/Codex-App-Manager) 只参考交互和来源适配；对方管理器安装包不能作 Codex 本体，对方 updater 不能接入本工具更新。
- 不统一使用清单顶层版本号。按平台/架构显示真实版本，区分应用显示版本和 MSIX 包版本，保留旧架构包时明确状态。
- 生产下载前锁定包记录（平台、架构、版本、长度、哈希、来源与 URL），下载中不重新解析 latest；从元数据获取临时 Windows URL，不长期硬编码。校验失败不安装，下载取消清理临时文件。
- SHA-256 比对证明内容与选定元数据一致，不等于发布者真实性。生产安装还需验证包签名与预期发布者；macOS 保留系统对签名、公证和下载隔离属性的检查，不自动删除隔离属性。
- Windows 使用 Store / MSIX 安装方式，保留系统确认；某些版本安装可能需要提权，不能承诺所有平台静默安装。macOS DMG 先下载校验，再由用户确认安装位置和替换操作；不绕过 Gatekeeper。
- [社区皮肤](https://github.com/Wangnov/awesome-codex-skins) 部分为个人使用许可。首版只做自有纯色；后续导入包先校验格式、哈希、路径和许可证，不运行包内脚本，不捆绑第三方图片素材。

**目前不需要用户补链接。** 若指定自己的镜像域名、下载代理或主题资源，再补充地址与维护方式即可。

## 实施顺序

1. 确认此原型视觉和页面层级，将现有汉化、重启确认、日志、关于接入对应页面；保持现有测试。
2. 独立 DownloadService：自动识别平台与架构，固定镜像源，进行版本比较、取消、校验、安装确认和权限失败提示；该方向已由 src/ 与 macos/ 中的原生实现推进。
3. ThemeService：先核实当前 Codex 的主题接口，再做可撤销的运行时样式适配、版本兼容探测；失败显示原因，不修改安装文件。工具配色和 Codex 样式分开保存。
4. Windows / macOS 分别做真实环境验收，再发布工具新版本。原型测试不等于 Codex 功能或 macOS 安装验收。

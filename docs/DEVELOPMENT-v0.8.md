# v0.8 原生开发与验收计划

## 交付边界

保留 WPF / SwiftUI 和现有本地汉化、路径验证关闭、自更新内核。将已确认的深色苹果质感原型落到原生五页界面；赞助信息固定左侧。网页原型不嵌入生产程序。

## 顺序与验证点

1. **基线**：Release 构建、现有 `--self-test`、临时进程关闭测试。不得关闭真实 Codex。
2. **设置与换肤服务**：校验预设 ID 和字体范围；原子保存；运行时只添加项目自有 style 标签，恢复时只移除该标签。仅连接本工具当前启动的会话，不扫描任意调试端口。验证实际计算样式，不将注入请求成功等同于整个界面完整适配。
3. **下载服务**：每次解析当前 manifest，但下载任务锁定平台、架构、版本、长度和 SHA-256。Windows 兼容 Microsoft catalog 的 Base64 SHA-256；不使用清单顶层版本冒充平台版本。流式写入独立临时文件，取消/失败删除未验证文件；校验通过才提供打开安装包按钮。官方 Windows 使用 Store。macOS 使用 DMG，不静默绕过系统安装确认。
4. **Windows 原生界面**：五页预先构建、切页不重建控制器或重复启动定时器。后台作业互斥，状态/日志始终可见；重启确认取消无副作用；UI 关闭时取消下载。保留标准系统窗口按钮。
5. **macOS 原生界面**：相同信息架构，原生材质与窗口控件；复用现有 LauncherModel 的汉化/关闭/更新。共享换肤脚本，独立平台下载适配。
6. **验收**：Release 构建、原有关闭测试、新服务边界检查、原生五页操作和最小窗口检查。真实 Codex 汉化/换肤、完整安装、macOS 双架构编译和实机验收单独记录。

## 防回归约束

- 不下载或执行社区皮肤脚本，不修改 app.asar，不清除 quarantine。
- 不把第三方管理器的安装包或 updater 接到本项目。
- 下载和自更新互斥；修改下载选项不改变进行中的任务。
- 页面验证、菜单验证、运行时配色验证是不同结果，不合并成一个“100% 成功”。
- 设置写入失败必须显示原因，不显示“已保存”。
- 不自动发布、提交或推送。macOS 本机不可构建时如实记录未验证。
